Síncrono: uma linha de cada vez, cada uma espera a anterior terminar. Assíncrono: você pede algo que demora (um timer, um dado da internet) e o programa segue em frente; quando ficar pronto, ele avisa. Analogia: você pede uma pizza e vai arrumar a mesa, não fica parado olhando para a porta.

  
Experimente: mude o tempo para 0. A pizza chega antes de arrumar a mesa?







  
setTimeout(função, ms) agenda a função para rodar uma vez, depois de um tempo em milissegundos (1000 ms = 1 segundo). Ele devolve um número de identificação; clearTimeout(id) cancela o agendamento.

  
Experimente: apague a linha do clearTimeout.







  
setInterval(função, ms) repete a função a cada intervalo, para sempre, até você chamar clearInterval(id). Esquecer o clearInterval é o "loop infinito" do mundo assíncrono.

  
Experimente: faça contar de 5 até 1.







  
Antes das Promises, a forma de "avisar quando terminar" era passar uma função de callback. Funciona, mas quando uma tarefa depende da outra, os callbacks ficam um dentro do outro: o famoso callback hell (código em pirâmide). As Promises resolvem isso.

  
Experimente: imagine mais 3 etapas nessa pirâmide. Dá para ler?







  
Uma Promise (promessa) é um objeto que representa um valor que ainda vai chegar. Ela tem 3 estados: pendente (esperando), resolvida (deu certo, chamou resolve) ou rejeitada (deu erro, chamou reject). Pense no comprovante do pedido: ainda não é a pizza, mas é a promessa de que ela vem.

  
Experimente: troque true por false na variável temPizza.







  
.then roda quando a Promise resolve (recebe o valor); .catch quando ela rejeita (recebe o erro); .finally roda sempre, no fim, dando certo ou não (ótimo para esconder um "carregando...").

  
Experimente: troque o id para 2.







  
Se um then devolve um valor (ou outra Promise), o próximo then recebe esse valor. Assim as etapas ficam uma embaixo da outra, sem pirâmide. Um único catch no fim pega o erro de qualquer etapa.

  
Experimente: adicione um terceiro then que mostra o total de pedidos.







  
async/await é um jeito de escrever código com Promises que parece síncrono. await "espera" a Promise resolver e já entrega o valor. Só pode ser usado dentro de uma função async (aqui no playground também funciona solto, como no console do navegador).

  
Experimente: tire o await da linha do buscarAluno e veja o que aparece.







  
Com async/await, os erros são tratados com try/catch: o código "tenta" no try; se alguma Promise rejeitar, pula direto para o catch. finally também existe aqui.

  
Experimente: troque o id para 1.







  
Com await uma depois da outra, os tempos somam. Quando as tarefas não dependem uma da outra, Promise.all roda todas ao mesmo tempo e espera a última. Se uma falhar, o all inteiro falha.

  
Experimente: compare os tempos mostrados nas duas formas.







  
Uma API é um endereço na internet que, em vez de uma página, devolve dados: você pede uma URL e recebe um texto em JSON (o mesmo formato do JSON.stringify da Aula 1). fetch(url) faz o pedido e devolve uma Promise com a resposta: status (200 ok, 404 não existe, 500 erro no servidor), ok (true se o status for 2xx), e o corpo, que você lê com .text() (texto cru) ou .json() (já convertido em objeto). As duas leituras também são assíncronas.

  
Experimente: troque a URL por https://viacep.com.br/ws/00000000/json/: o status continua 200, mas o JSON vem com erro.







  
fetch(url) busca dados na internet e devolve uma Promise com a resposta. A resposta chega como texto, então usamos await resposta.json() para virar objeto (o JSON da aula passada!). Aqui usamos a API pública ViaCEP.

  
Experimente: coloque o CEP da sua casa (só números).







  
APIs costumam devolver listas de objetos, e aí entra tudo da Aula 1 (map, filter...). Sempre confira resposta.ok (false quando o servidor responde com erro, como 404) e trate falhas de rede com try/catch.

  
Experimente: troque a URL para /users/999 e veja o tratamento do 404.







  
Antes de executar, tente adivinhar a ordem! Primeiro roda todo o código síncrono. Depois as Promises já resolvidas (then). Por último os timers, mesmo com 0 ms. Esse "organizador de filas" do JavaScript se chama event loop.

Existem milhares de APIs públicas e gratuitas, e todas funcionam do mesmo jeito: uma URL, um JSON. A PokéAPI devolve tudo sobre qualquer Pokémon pelo nome: https://pokeapi.co/api/v2/pokemon/pikachu. Repare como os dados vêm aninhados: os tipos são uma lista de objetos, e cada um tem um objeto type com o name; o map da Aula 1 resolve.

A BrasilAPI reúne dados públicos do Brasil, de graça e sem cadastro: CEP, feriados nacionais, bancos pelo código, cidades de um DDD, CNPJ, tabela FIPE. Cada endpoint (caminho da URL) devolve um tipo de dado. Aqui três deles, um atrás do outro com await.

Nem toda API devolve dados fixos: a Open-Meteo devolve o clima de agora para qualquer latitude e longitude, e muda a cada 15 minutos. Repare nos parâmetros da URL depois do ?: latitude=...&longitude=...&current_weather=true. É assim que você diz à API o que quer.

  
Experimente: coloque a latitude e longitude da sua cidade (procure no Google Maps: clique com o botão direito no mapa).







  
A AwesomeAPI devolve a cotação de moedas em tempo real: https://economia.awesomeapi.com.br/last/USD-BRL. Os números vêm como texto ("5.06"): converta com Number() antes de calcular, e formate com toFixed(2). É o tipo de API que um site de loja ou de viagem consome.

  
Experimente: troque por EUR-BRL ou BTC-BRL, e converta um valor em reais para dólar.







  
A API do GitHub devolve o perfil público de qualquer usuário: https://api.github.com/users/octocat. É a mesma API que o site do GitHub usa. Sem login ela permite 60 pedidos por hora por conexão; se passar, devolve 403 (por isso o ok).
