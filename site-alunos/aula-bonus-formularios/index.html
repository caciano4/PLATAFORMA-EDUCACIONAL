Um <form> agrupa campos e tem um botão de enviar. Ao clicar nele (ou apertar Enter num campo), o navegador dispara o evento submit e, do jeito antigo, recarrega a página mandando os dados para um servidor. Execute e clique em Enviar: repare na faixa vermelha.

  
Experimente: digite um nome, clique em Enviar e veja o campo ser apagado pelo "recarregamento".








  
evento.preventDefault() cancela o comportamento padrão (o recarregamento). A partir daí, quem decide o que fazer com os dados é o seu código. Essa é a primeira linha de quase todo submit.

  
Experimente: aperte Enter dentro do campo. Também dispara o submit?








  
Dentro do submit, leia cada campo com .value. Sempre vem como texto: para números use Number(). .trim() tira espaços das pontas.

  
Experimente: deixe a idade em branco e veja o que Number("") devolve.








  
Cada tipo de campo tem seu jeito: checkbox usa .checked (true/false); radio usa querySelector("input[name=plano]:checked") para achar o marcado; select usa .value da opção escolhida.

  
Experimente: mude as opções e envie de novo.








  
Validar é conferir os dados antes de usar: campo vazio, número fora do limite, e-mail sem @. Se algo está errado, mostre a mensagem e pare (return). Lembra do truthy/falsy? if (!nome) pega o texto vazio.

  
Experimente: envie com o nome vazio, depois com a idade 200.








  
O HTML já valida um pouco sozinho: required (obrigatório), type="email", min/max, minlength. Se algo falha, o submit nem dispara e o navegador mostra o balão. Use as duas camadas: HTML para o básico, JavaScript para as regras do seu negócio.

  
Experimente: envie vazio e veja o balão do navegador. Depois apague o required no HTML mentalmente: o JS teria que cuidar disso.








  
O evento input dispara a cada tecla. Serve para contadores de caracteres, prévia ao vivo e validação instantânea. evento.target é o campo que disparou.

  
Experimente: limite em 20 e mude a cor quando passar (classList).








  
change dispara quando o valor "fecha" (select, checkbox, ou ao sair do campo). form.reset() limpa tudo. E dá para desabilitar o botão até o formulário estar válido.

  
Experimente: marque e desmarque o checkbox e veja o botão ligar e desligar.








  
Com name em cada campo, new FormData(form) lê todos de uma vez e Object.fromEntries transforma num objeto (Aula 1!). É exatamente esse objeto que você mandaria para uma API com fetch.

  
Experimente: acrescente um campo com name="cidade" no HTML e veja aparecer no objeto sem mudar o JS.








  
O padrão completo: submit → validar → montar o objeto → guardar no array → renderizar a lista → limpar o form. É assim que funcionam listas de tarefas, carrinhos e cadastros.

  
Experimente: mostre também o total de cadastrados.








  
Um formulário completo para testar o que quiser.

  
Dica: comece sempre pelo preventDefault().








  
🎯 Objetivo: Fazer o submit mostrar uma mensagem sem recarregar a página.
O que fazer
  1. Selecione o #f e escute o evento submit.
  2. Na primeira linha do callback, evento.preventDefault().
  3. Coloque "Enviado!" no #resultado.
Resultado esperado
Clicou em Enviar → "Enviado!"
Sem faixa vermelha de recarregamento

  
Depois de acertar, teste também: Tire o preventDefault e veja a faixa vermelha.









  
🎯 Objetivo: Ler o nome digitado e cumprimentar ao enviar.
O que fazer
  1. No submit (com preventDefault), leia #nome com .value.
  2. Mostre `Olá, ${nome}!` no #resultado.
Resultado esperado
Digitou Ana + Enviar → "Olá, Ana!"

  
Depois de acertar, teste também: Use .trim() e teste digitando espaços antes do nome.









  
🎯 Objetivo: Não aceitar o envio com o nome vazio.
O que fazer
  1. No submit, leia o nome com .value.trim().
  2. Se estiver vazio (if (!nome)), mostre "Digite o nome" no #erro e return.
  3. Senão, limpe o #erro e mostre `Cadastrado: ${nome}` no #resultado.
Resultado esperado
Vazio + Enviar → erro "Digite o nome"
Ana + Enviar → "Cadastrado: Ana"

  
Depois de acertar, teste também: Faça o erro sumir assim que a pessoa começar a digitar (evento input).









  
🎯 Objetivo: Mostrar quantos caracteres foram digitados, em tempo real.
O que fazer
  1. Escute o evento input do #msg.
  2. A cada tecla, mostre `${msg.value.length} / 100` no #contador.
Resultado esperado
Digitou "Olá" → "3 / 100"

  
Depois de acertar, teste também: Adicione a classe vermelho no contador quando passar de 90.









  
🎯 Objetivo: Só confirmar se o checkbox estiver marcado.
O que fazer
  1. No submit (com preventDefault), leia #termos com .checked.
  2. Se não estiver marcado, mostre "Aceite os termos" no #resultado.
  3. Se estiver, mostre "Confirmado!".
Resultado esperado
Desmarcado → "Aceite os termos"
Marcado → "Confirmado!"

  
Depois de acertar, teste também: Desabilite o botão até o checkbox ser marcado (evento change + disabled).









  
🎯 Objetivo: Mostrar uma mensagem diferente conforme a opção escolhida.
O que fazer
  1. No submit, leia #curso com .value.
  2. Mostre `Você escolheu ${curso}` no #resultado.
Resultado esperado
Escolheu php → "Você escolheu php"

  
Depois de acertar, teste também: Use um switch para mostrar o nome completo de cada curso.









  
🎯 Objetivo: Somar dois números digitados (de verdade, não juntar textos).
O que fazer
  1. No submit, leia #a e #b e converta com Number().
  2. Mostre `Soma: ${a + b}` no #resultado.
Resultado esperado
2 e 3 → "Soma: 5" (e não "Soma: 23")

  
Depois de acertar, teste também: Adicione um select com a operação (+, −, ×) e use switch.









  
🎯 Objetivo: Transformar o formulário num objeto e mostrar como JSON.
O que fazer
  1. No submit, crie const dados = Object.fromEntries(new FormData(form));
  2. Mostre JSON.stringify(dados) no #saida.
Resultado esperado
Ana + ana@email.com → {"nome":"Ana","email":"ana@email.com"}

  
Depois de acertar, teste também: Converta a idade com Number() antes de mostrar.









  
🎯 Objetivo: Adicionar cada tarefa digitada na lista, sem aceitar vazio, e limpar o campo.
O que fazer
  1. No submit (com preventDefault), leia #tarefa com .value.trim(); se vazio, return.
  2. Crie um li com o texto e adicione em #lista.
  3. Limpe o formulário com form.reset().
Resultado esperado
Digitou "Estudar" + Enter → item "Estudar" na lista
Campo limpo depois

  
Depois de acertar, teste também: Guarde as tarefas num array e renderize a lista a partir dele.









  
🎯 Objetivo: Validar nome, e-mail e idade com mensagens específicas, e só cadastrar se tudo estiver certo.
O que fazer
  1. Leia nome (.trim()), email e idade (Number()).
  2. Regras: nome vazio → "Digite o nome"; e-mail sem @ (!email.includes("@")) → "E-mail inválido"; idade menor que 18 → "Só para maiores de 18".
  3. Mostre a primeira mensagem de erro no #erro e pare. Se tudo ok, limpe o erro e mostre `Bem-vindo, ${nome}!` no #resultado.
Resultado esperado
ana@email → "E-mail inválido"
idade 15 → "Só para maiores de 18"
tudo ok → "Bem-vindo, Ana!"

  
Depois de acertar, teste também: Guarde cada cadastro válido num array e mostre o total.
